# cc-connect-pro Desktop Client Design

**Date:** 2026-06-15
**Status:** Approved

## Summary

Create a macOS/Windows desktop client for cc-connect-pro using Wails (Go + React + Tailwind). The client embeds the cc-connect service process, provides system tray integration, and manages Feishu app credentials, Agent status/task queues, and server health monitoring. Visual design follows Apple HIG principles — extreme simplicity, generous whitespace, restrained accent usage, and a single signature animation element.

## Architecture Choice

**Approach A: Independent Wails sub-project** (chosen over B: deep-embed, C: separate repo)

- New `client/` directory within cc-connect-pro, with its own Wails build pipeline
- Go side directly imports `config/`, `daemon/`, `core/` packages — full code reuse
- Frontend shares components/i18n types with existing `web/src/`
- Wails build is independent from existing Makefile/build tags system

## Embedded Service Architecture

### Startup Flow

1. User opens client → `main.go` initializes Wails App
2. `app.go` checks `~/.cc-connect/config.toml` existence
3. No config → frontend shows welcome wizard:
   - Enter Feishu app_id/app_secret (required)
   - Select Agent type (dropdown: claudecode/codex/cursor/gemini etc.)
   - Set work_dir (optional)
   - Call `config.EnsureProjectWithFeishuPlatform()` → auto-create project + write config
   - Auto-start service
4. Config exists → `service.go` calls `config.Load()` and starts Engines
5. Each Engine starts its Platforms (Feishu via WebSocket long-connection)

### Service State Machine

```
idle → starting → running → stopping → idle
                ↘ error → idle (manual restart required)
```

- State pushes via `EventsEmit("service:status", status)`
- Errors push via `EventsEmit("service:error", errMsg)`

### App Struct — Go Methods Exposed to Frontend

```go
type App struct {
    ctx    context.Context
    engines []*core.Engine  // multiple engines for multiple projects
}

// Configuration management
func (a *App) LoadConfig() (*ConfigSummary, error)
func (a *App) SaveFeishuCredentials(opts FeishuCredOpts) error
func (a *App) GetProjects() []ProjectInfo
func (a *App) CreateProject(opts CreateProjectOpts) error

// Service management
func (a *App) StartService() error
func (a *App) StopService() error
func (a *App) RestartService() error
func (a *App) GetServiceStatus() ServiceStatus

// Agent management
func (a *App) ListSessions() []SessionInfo
func (a *App) GetAgentStatus() []AgentStatusInfo
func (a *App) StopSession(id string) error

// Monitoring
func (a *App) GetHealthCheck() HealthReport
func (a *App) GetTaskQueue() []TaskInfo
func (a *App) GetRecentLogs(count int) []LogEntry
```

### System Tray

| Menu item | Function |
|-----------|----------|
| cc-connect - Running | Dynamic status text |
| Show Window | Restore hidden main window |
| Restart Service | StopService() → StartService() |
| View Logs | Navigate to Monitor page |
| ─── separator ─── | |
| Quit | Graceful shutdown all Engines → exit process |

- Close window = hide to tray (not quit)
- True exit only via tray "Quit" or Cmd+Q
- Tray icon: abstract "connection" symbol (two nodes + line), Accent color when running, gray when stopped

### Config Hot-Update

- Frontend edits → Go side calls `config.SaveFeishuCredentials()` → writes TOML
- If service running, triggers Platform reconnect (Feishu WebSocket auto-reconnects)
- If service stopped, changes apply on next start

### Code Reuse Map

| Feature | Reuse source | Method |
|---------|-------------|--------|
| Config load/save | `config/config.go` | Direct import |
| Feishu credential write | `config.EnsureProjectWithFeishuPlatform` | Direct import |
| Engine create/start | `core.NewEngine()`, `e.Start()` | Direct import |
| Agent/Platform registration | `plugin_*.go` init() | Import triggers registration |
| Daemon management | `daemon/manager.go` | Direct import (optional: tray replaces daemon) |
| Graceful shutdown | `main.go` shutdown logic | Extract to `service.go` or shared helper |

## Visual Design System

### Design Philosophy

cc-connect-pro is a "connection" — a bridge between AI agents and messaging platforms. The visual language conveys precision, real-time awareness, and trustworthiness. Apple restraint is the baseline; identity comes from the "connection" theme itself.

### Color Palette

| Role | Light mode | Dark mode | Usage |
|------|-----------|----------|-------|
| Canvas | `#FFFFFF` | `#1C1C1E` | Page background, largest area |
| Surface | `#F5F5F7` | `#2C2C2E` | Cards, sidebar, popovers |
| Accent | `#5856D6` | `#7B79E0` | Primary action color — indigo, "intelligent connection" |
| Success | `#34C759` | `#30D158` | Online / running status |
| Warning | `#FF9500` | `#FF9F0A` | Warning / queue backlog |
| Text Primary | `#1D1D1F` | `#F5F5F7` | Body & titles |
| Text Secondary | `#86868B` | `#A1A1A6` | Subtext, labels |

No gradient buttons. No large gradient backgrounds. Accent appears only on interactive elements (buttons, selected state, active indicators). Everything else uses grayscale hierarchy.

### Typography

- **Title/Body:** System font stack (`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif`) — SF Pro on macOS, Segoe UI on Windows
- **Data/Code:** `ui-monospace, "SF Mono", "Cascadia Code", Menlo, monospace` — for session IDs, queue numbers, status codes
- **Type scale:** Large Title (28px) → Title (20px) → Headline (17px bold) → Body (15px) → Caption (12px) → Mini (10px), matching Apple HIG

### Layout

- Sidebar: 220px, no divider, selected item uses left-side 3px Accent capsule indicator (Apple Settings style)
- Content padding: 32px, card gap: 16px
- Cards: no border, Surface background only, 8px radius
- Mode switches use Segmented Control (Apple-style), not tabs
- Form inputs: 1px border, 6px radius, focus → Accent border

### Signature Element

Dashboard top: "connection bridge" animation — Agent icon and Platform icon connected by a thin line. When running, a faint Accent-colored light dot slowly travels along the line, indicating real-time message flow. When stopped, line turns gray, dot disappears. This is the only animation element; all other pages have zero animation.

### Control Style Rules

| Control | Rule |
|---------|------|
| Button | Accent bg + white text (primary), Surface bg + gray text (secondary), radius ≤ 8px |
| Status | 6px dot + text label, no badge/pill |
| List | Borderless rows, 1px light-gray divider, hover → Surface background |
| Form | Label above input, minimal input style, errors shown inline in Warning color |
| Empty state | One guiding sentence + one action button, no illustration |

## Frontend Pages

### Page 1: Dashboard (Service Status Overview)

- Service status indicator (running / stopped / error)
- Each Platform connection status (Feishu WebSocket online?)
- Each Agent status summary (active session count, queue depth)
- Quick actions: start / stop / restart service
- Recent event log (last 10 entries)
- Signature element: connection bridge animation at top

### Page 2: FeishuConfig (Feishu Credentials & Workspace Management)

- **Workspace list:** configured `[[projects]]`, each showing name, Agent type, Feishu Platform status
- **New workspace:** form for project name, Agent type (dropdown), work_dir
- **Feishu credentials:** per-project Platform editing — app_id, app_secret, domain
- **Permissions & behavior:** allow_from, allow_chat, group_only, reaction_emoji, etc. — grouped display
- **Connection mode switch:** WebSocket (default) vs Webhook (via Segmented Control) — Webhook mode shows port, callback_path, encrypt_key
- **Credential validation:** button to call Feishu API verify app_id/app_secret
- Save triggers hot-update to running Engine

### Page 3: Agents (Agent Status & Task Queue)

**Session list (each row):**

| Display | Format |
|---------|--------|
| Session ID | Mono font, truncated 8 chars + "…" |
| Agent type | Label, e.g. "Claude Code" |
| Platform | "Feishu" + source chat name |
| Project name | Corresponding `[[projects]]` name field |
| Status | Dot: green=active, gray=idle, red=error |
| Created time | Caption, relative time "5 min ago" |

**Task queue:**

- Queue depth (pending message count)
- Each queued message: Platform source, username, **message content summary (truncated 60 chars)**, queue duration
- Queue empty → entire section hidden (no placeholder)

**Session detail panel:**

- Click row → right-side slide-in panel (Apple Mail style)
- Last 5 message summaries (user sent + agent replied)
- Current Provider/Model
- Action: stop this session

**Actions:**

- Stop session → `session.Close()`
- Clear queue → button with confirmation, drops queued messages
- Force reconnect → Feishu Platform only, reset WebSocket

### Page 4: Monitor (Server Health)

**Process info card:**

- PID, uptime, memory (MB), goroutine count
- All data in Mono font, labels in Caption
- 2-column grid layout

**Platform health card:**

- Feishu: WebSocket connection status, reconnect count, message send/receive counts
- Same structure for other Platforms
- Dot + number, no progress bars or gauges

**Log viewer:**

- Hook Go `slog` output: write to in-memory ring buffer (last 500 entries) in `service.go`
- Frontend real-time scroll display, auto-pause on manual scroll
- Level color dots: ERROR=red, WARN=orange, INFO=gray, DEBUG=light gray

**Doctor check:**

- Agent CLI binary existence (`AgentDoctorInfo.CLIBinaryName()`)
- Version match check
- Results: simple list with ✓ or ✗ + description

## Testing Strategy

- Go side: unit tests for `service.go` (start/stop/restart state machine), `app.go` method tests
- Frontend: component rendering tests with Vitest for key pages
- Integration: Wails dev mode manual testing for tray, service lifecycle, config hot-update
- Existing `go test ./...` must still pass unchanged

## Scope Boundaries

- Client does NOT replace the existing Web UI or CLI — it's an optional desktop companion
- Client does NOT implement chat/message viewing — that remains in the messaging platforms
- Client does NOT support multi-user auth — single-user, local-only desktop tool
- Client only manages Feishu/Lark credentials; other platform configs remain in TOML editing
